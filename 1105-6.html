图一 · 智能客服问答处理流程图（flowchart）

用户提问后经过：意图识别 → 知识检索 → 置信度判断的三级分流，低置信度转人工并沉淀知识，答案经安全过滤后返回。

flowchart TD
    A([用户发起提问]) --> B[API 网关
鉴权 / 限流]
    B --> C[会话管理
加载多轮上下文]
    C --> D{意图识别}
    D -->|闲聊寒暄| E[闲聊话术模板
直接回复]
    D -->|业务咨询| F[问题改写
Query Rewrite]
    D -->|投诉报障| G[创建工单
通知人工跟进]
    F --> H[(向量知识库
Embedding 召回 Top-K)]
    H --> I[重排序
Cross-Encoder 精排]
    I --> J{置信度是否达标}
    J -->|是| K[LLM 生成答案
Prompt = 问题 + 知识片段]
    J -->|否| L[转人工客服]
    K --> M{答案安全过滤}
    M -->|通过| N[返回答案
附引用来源]
    M -->|不通过| O[拒答并记录日志]
    L --> P([人工解答])
    E --> N
    G --> P
    N --> Q[(问答日志库)]
    O --> Q
    P --> Q
    Q -->|标注 / 评估| R[知识运营后台
知识更新与模型微调]
    R -.补充知识.-> H

图二 · 智能客服知识库数据模型（ER 图）

核心实体：用户、会话、消息、知识条目、知识分类、工单。一条会话包含多条消息；消息命中知识条目；低置信度消息可升级为工单。

erDiagram
    USER ||--o{ SESSION : "发起"
    SESSION ||--o{ MESSAGE : "包含"
    MESSAGE }o--o{ KNOWLEDGE : "命中引用"
    KNOWLEDGE }o--|| CATEGORY : "属于"
    MESSAGE ||--o| TICKET : "升级为"
    TICKET }o--|| USER : "分配给客服"

    USER {
        bigint user_id PK "用户ID"
        varchar nickname "昵称"
        varchar role "角色: customer/agent/admin"
        datetime created_at "注册时间"
    }
    SESSION {
        bigint session_id PK "会话ID"
        bigint user_id FK "所属用户"
        varchar channel "渠道: web/app/wechat"
        tinyint status "状态: 进行中/已结束/转人工"
        datetime started_at "开始时间"
    }
    MESSAGE {
        bigint message_id PK "消息ID"
        bigint session_id FK "所属会话"
        tinyint sender "发送方: 用户/机器人/客服"
        text content "消息内容"
        float confidence "答案置信度"
        int tokens "token消耗"
        datetime created_at "发送时间"
    }
    KNOWLEDGE {
        bigint knowledge_id PK "知识ID"
        bigint category_id FK "分类ID"
        varchar title "问题标题"
        text answer "标准答案"
        vector embedding "语义向量"
        tinyint review_status "审核状态"
        datetime updated_at "更新时间"
    }
    CATEGORY {
        bigint category_id PK "分类ID"
        varchar name "分类名称: 退款/物流/账户"
        bigint parent_id FK "父分类"
    }
    TICKET {
        bigint ticket_id PK "工单ID"
        bigint message_id FK "来源消息"
        bigint agent_id FK "受理客服"
        varchar priority "优先级"
        varchar status "状态: 待处理/处理中/已解决"
        datetime resolved_at "解决时间"
    }
